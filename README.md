# 物流員工管理系統

依據 `logistics_system_prompt.md` 規格實作的物流員工日常作業管理系統，涵蓋首頁公告與行事曆、每日送件記錄、車輛里程記錄、今日角色、請假申請與審核、薪資計算（含薪資單 PDF）、貨運行 Excel 對帳、車輛管理與保養提醒（含每台車保養／保險／油資花費總覽與 Excel 匯出）、員工帳號管理、管理者儀表板、加油回報與審核、停車費回報與審核。

詳細開發歷程與各功能決策請見 `討論紀錄_2026_06_14.md`。

## 技術架構

- **後端**：Node.js + Express + TypeScript + Prisma + PostgreSQL
- **前端**：React + Vite + TypeScript + Tailwind CSS + React Router
- **認證**：JWT（第一個註冊的帳號自動成為董事長 ADMIN；後台「開放員工自行註冊」開關關閉時，`/register` 僅允許建立第一個帳號）
- **角色**：
  - **ADMIN（董事長）**：完整權限。
  - **MANAGER（執行長）**：填寫自己的每日送件記錄、車輛里程、今日角色；可查看員工列表、薪資查詢、派遣紀錄、貨運行對帳、管理者儀表板；可編輯任一員工的今日角色、車輛保養項目與維修登記、行事曆活動、首頁公告，並可審核／拒絕／刪除請假申請、油資審核、停車費審核。員工帳號與角色管理、送件/里程紀錄編輯刪除、薪資扣款、對帳上傳、後台基礎設定、員工歷史紀錄清理僅 ADMIN 可操作。
  - **EMPLOYEE（員工）**：僅能存取自己的每日送件記錄、車輛里程、薪資、請假申請、加油回報、停車費回報。
- **部署**：Railway（push 到 GitHub `main` 分支後自動重新部署並執行 `prisma migrate deploy`），本機開發以 `npx prisma generate` / `npx tsc --noEmit` / `npm run build` 做語法檢查為主

## 專案結構

```
backend/   Express API（路由、Prisma schema、薪資/對帳/車輛等業務邏輯）
frontend/  React 前端（員工/管理者頁面、路由、API client）
```

## 啟動方式

正式環境部署於 Railway（PostgreSQL），本機開發環境無法連接該資料庫，因此本機僅用於語法/型別檢查與前端介面開發：

### 1. 後端 API（語法檢查／編譯）

```powershell
cd backend
npm install
npm run prisma:generate
npx tsc --noEmit
npm run build
npm test          # 執行 Vitest 單元測試（薪資計算邏輯）
```

環境變數設定於 `backend/.env`（可參考 `.env.example`）：

```
DATABASE_URL="postgresql://..."
JWT_SECRET="change-this-secret-in-production"
JWT_EXPIRES_IN="7d"
PORT=4000
```

### 2. 前端網站（預設 http://localhost:5173）

```powershell
cd frontend
npm install
npm run dev
```

前端開發伺服器已設定 `/api` proxy 轉發至後端的 `http://localhost:4000`，因此開發時兩個伺服器需同時啟動（後端需連到可用的 PostgreSQL）。

## 帳號

- 第一個透過「註冊」建立的帳號會自動成為董事長（ADMIN）。
- 後台「開放員工自行註冊」開關關閉後，`/register` 僅允許建立第一個帳號，其餘員工帳號由董事長於「員工管理」建立。
- 正式環境（Railway）已有兩組測試帳號，可直接登入體驗各模組：
  - 董事長：`test-admin@example.com` / `test1234`
  - 一般員工：`test-employee@example.com` / `test1234`

## 已實作的模組

1. **首頁（公告欄＋行事曆）**：單則公告（ADMIN/MANAGER 可編輯，EMPLOYEE 唯讀）；當月行事曆整合公司活動與已核准請假，任何人點擊日期可查看當日請假、活動明細（ADMIN/MANAGER 可新增/刪除活動）。
2. **每日送件記錄**：正/逆物流件數、備註、今日角色（無/貨車司機/貨車隨車人員），每人每日一筆（重新填寫即覆蓋）；管理者可在薪資計算頁的每日明細中新增、編輯或刪除任一員工任一天的送件記錄（會同步刪除當日角色登記）。
3. **車輛里程記錄**：機車（必填）/貨車（選填）下拉選單，每天僅需填寫「今日結束里程」（累計里程），系統自動以該車輛前一筆紀錄計算當日行駛里程；管理者可在派遣紀錄頁編輯或刪除任一筆里程紀錄。
4. **請假申請與審核**：員工可申請/查看/取消請假，ADMIN/MANAGER 於「請假管理」頁核准、拒絕或刪除任何請假申請。
5. **薪資計算**：每件單價 = 固定原始單價 + 出勤天數加給（15/20/25 天三階疊加）+ 日均件數加給（達門檻）+ 當月總件數加給（達門檻），整月固定套用同一單價（依所屬「職等」各自設定門檻與加給金額）；含職務加給、貨車司機/隨車加給、激勵獎金（出勤≥25天且日均件數>60→+3000，>30→+1500，與每件單價加給是獨立兩套機制）、油資補貼（已核准加油回報加總）、停車費補貼（已核准停車費回報加總）、扣款項目；薪資計算頁以獨立欄位明確顯示每位員工當月應補貼的油資與停車費（表尾另有全員合計），展開明細可逐筆查看回報日期/金額/備註；單一員工薪資單匯出 PDF（內嵌 Logo 與思源黑體，含每日明細與薪資計算說明），全公司薪資總表匯出 Excel。
    - **月份封存（快照）**：ADMIN 可於薪資計算頁「封存本月薪資」，將當下每位員工的計算結果凍結為快照；封存後薪資頁/我的薪資/薪資單 PDF 一律改讀快照，不再受日後資料補登或薪資公式調整影響，員工端照常可見但金額固定。封存月份禁止編輯送件/角色/扣款，需先「解除封存」（解封與重封皆留紀錄）。系統設定可設「薪資封存提醒日」（預設次月 5 日），逾期未封存時儀表板「待處理事項」會提醒（不自動封存，由管理者手動決定，等同保留寬限期）。
6. **派遣紀錄**（已併入營運總覽「送件與派車」分頁）：依每日角色與里程紀錄即時統計「當天誰開哪輛車、誰是貨車司機/隨車人員」；ADMIN/MANAGER 可校正任一在職員工當天的今日角色，即使該員工當天沒有車輛使用紀錄。
7. **貨運行 Excel 對帳**：上傳月結 Excel（讀取第一個工作表/總表，以關鍵字定位數值），分別顯示「件數比對」與「金額比對」，差異依正負以紅字／綠字標示。
8. **車輛管理（維修站模式）**：以「車輛卡片牆＋健康燈號」呈現（紅＝需處理／黃＝即將到期／綠＝正常），點卡片開啟詳情 Modal，分「保養項目／維修履歷／花費總覽／證件稅務／使用紀錄／基本資料」分頁：
    - **保養提醒（里程＋時間雙週期）**：每個保養項目可設定 `intervalKm` 與選填的 `intervalDays`，里程或天數先到先提醒；剩餘量低於週期 20% 黃字、逾期紅字。保養項目可直接編輯名稱／里程週期／時間週期（不需刪除重建），亦可新增/刪除自訂項目。
    - **維修保養履歷（含費用、可分類、可編輯）**：每次「登記維修」自動寫入永久履歷（日期、里程、項目、費用、廠商／技師、備註、登記人），即使日後刪除保養項目仍保留；亦可「手動新增花費」記錄非週期性項目並選擇分類（保養／維修、保險、其他），費用可留空。每筆履歷皆可**編輯或刪除**。詳情頁以時間軸呈現，並統計累計／今年／本月花費。
    - **花費總覽（每台車個別花費）**：彙整每台車的**保養／維修、保險、油資、其他**四類花費——保養／保險／其他來自維修履歷，油資來自「已核准」加油回報。可切換統計期間（**全部時期／某年／某年某月**），選定年份時顯示各月小計表；並可**匯出 Excel**：本車花費明細（依所選期間，含分類小計）與全車隊花費總表（每台車 × 各分類 ＋ 全隊總計）。
    - **證件／稅務到期提醒**：可登錄強制險、第三人責任險、驗車、牌照稅、燃料稅到期日，到期前 30 天黃字、逾期紅字。
    - 新建車輛自動依車型建立預設保養項目；變更車型會重置為新車型預設；車輛使用歷史紀錄協助判斷停用。
9. **員工管理**（三分頁整合）：
    - **員工資料**：姓名/Email、帳號啟用/停用、重設密碼、刪除帳號（僅 ADMIN，且無歷史紀錄才可直接刪除）、查看歷史紀錄，以及**指派職務**（單選）。
    - **職務加給設定**：建立/管理「職務」清單（如車輛管理組長、人員運能組長），每個職務設定固定月加給金額**＋解鎖的模組權限**（capabilities）。
    - **權限設定**：帳號角色（ADMIN/MANAGER/EMPLOYEE）設定。
    - **職務權限（capabilities）**：員工被指派含模組權限的職務後，即解鎖對應模組——`MANAGE_VEHICLES`→車輛管理/維修管理、`MANAGE_FINANCE`→記帳、`PROXY_DELIVERY`→代填送件。角色階層不變，職務權限為疊加授權；破壞性操作（如刪除車輛）仍限 ADMIN。固定職務加給會計入薪資 `jobAllowance`。
10. **員工紀錄管理**（僅 ADMIN）：可查看單一員工所有歷史紀錄，逐筆刪除或一鍵清空（需輸入員工姓名確認），供刪除帳號前清空資料使用。
11. **後台基礎設定**（僅 ADMIN）：薪資封存提醒日、每月正/逆物流實拿單價（直接輸入，單一表格新增／修改／刪除）、註冊開關。薪資公式（每件單價與其出勤/日均/總件數加給門檻、司機／隨車日加給、激勵獎金條件）依職等於「職等薪資設定」頁各自設定。（員工職務加給與權限已移至「員工管理」頁。）
12. **營運總覽**（路由 `/admin`，原「管理者儀表板」）：四個分頁——
    - **總覽**：月結算統計（件數、預估薪資、預估收入、預估毛利）與每日件數趨勢。
    - **每日營運**：依選定年月列出每一天的總正/逆物流、薪資、營收、盈餘、出勤人數、司機、跟車，並於表尾顯示平均與總計；可一鍵「匯出當月送件狀況」Excel。
    - **送件與派車**：選一天，上半看誰還沒填送件（可代填代管帳號），下半看派車與今日角色（可校正角色、編輯／刪除里程）。
    - **車輛狀況**：顯示車輛目前累計里程、保養狀態與今日使用情形。
    - 待處理提醒改由首頁「我的待辦」（`GET /api/home/todos`）統一提供，依身分列出送件、審核、單價、薪資封存、記帳、車輛保養／證件等待辦。
13. **側邊導覽列**：依角色顯示對應選單，依「核心作業／物流與派遣／回報與審核／人事行政／薪資／系統設定」等部門分類分區呈現（員工端回報區命名為「回報作業」，僅有加油/停車費回報）。
14. ~~區域管理~~：已移除（區域管理、我的區域與區域主管權限一併移除；Region／RegionMember 資料表暫予保留）。
15. **薪資計算公式設定**（僅 ADMIN，於「系統設定」頁）：可調整每件單價與其出勤/日均件數/總件數加給門檻、貨車司機/隨車人員加給、激勵獎金條件與金額，並填寫公式說明文字（顯示於薪資計算頁與我的薪資頁）。
16. ~~排班系統~~：已於 v1.34 移除（Schedule 資料表保留歷史資料）。
17. **我的申請**（路由 `/requests`，全體）：加油、停車費、車輛報修、請假四個分頁。加油／停車費填日期、金額、車輛類型（機車/貨車）與車牌、備註，待審核可撤回，已核准金額計入當月薪資（油資／停車費補貼）。
18. **審核中心**（路由 `/review`，ADMIN/MANAGER；具 `MANAGE_VEHICLES` 者僅報修分頁）：「全部待處理」依送出時間列出所有待辦並可直接核准；油資、停車費分頁含待審核／歷史紀錄／各車彙整，請假與報修分頁同原功能。分頁與側邊欄顯示待處理件數（`GET /api/review/summary`）。加油與停車費後端共用 `expenseReport.routes.ts`。舊網址自動轉址。
19. （已併入第 17、18 項）

## 開發狀態 / 後續可優化方向

- 詳細功能演進與決策記錄於 `討論紀錄_2026_06_14.md`，目前所有已討論需求皆已完成並部署。

- 薪資、對帳等規則若需依實際營運微調（例如每件單價門檻），可於後台「系統設定」調整，或修改 `backend/src/services` 內對應檔案。
